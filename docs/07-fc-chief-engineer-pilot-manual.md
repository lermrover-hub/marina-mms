# คู่มือทดลองใช้ Marina MMS สำหรับ FC และ Chief Engineer

**ระบบ:** Marina MMS Preview
**สภาพแวดล้อม:** Vercel Preview เชื่อมต่อ Supabase Staging
**ฉบับ:** 1.0 วันที่ 14 กันยายน 2026
**ผู้ใช้:** Finance Controller และ Chief Engineer

## 1 วัตถุประสงค์

คู่มือนี้ใช้สำหรับตรวจสอบว่า Marina MMS รองรับงานการเงินและงานอู่เรือตามกระบวนการจริงหรือไม่ ผู้ทดสอบต้องตรวจข้อมูลเฉพาะส่วนที่เกี่ยวข้องกับหน้าที่ของตน บันทึกข้อผิดพลาดและข้อเสนอแนะ และหลีกเลี่ยงการใช้ข้อมูลหรือธุรกรรมจริงจนกว่าจะผ่านการอนุมัติเปิดใช้งาน Production

ข้อสรุปด้านความรับผิดชอบคือ **ไม่ควรให้ Admin รับผิดชอบข้อมูลทั้งหมดเพียงคนเดียว** Admin ควรดูแลบัญชีผู้ใช้ สิทธิ์ โครงสร้างระบบ และการเปลี่ยนแปลงระดับระบบ ส่วน FC เป็นเจ้าของข้อมูลราคา บัญชี และรายงาน และ Chief Engineer เป็นเจ้าของข้อมูลต้นทุนหน้างาน ปริมาณงาน วัสดุ ค่าแรง และผู้รับเหมาช่วง

## 2 การเข้าใช้งาน

1. เปิด Shareable Link ของ Marina MMS Preview ที่ได้รับจาก Admin
2. ตรวจว่า URL เป็นโดเมน `vercel.app` ของโครงการ Marina MMS
3. ที่หน้า Sign in ให้ใช้ชื่อผู้ใช้ของตนเอง
4. ใช้รหัสผ่านที่ Admin ส่งให้ผ่านช่องทางแยกจากลิงก์
5. หลังเข้าสู่ระบบ ตรวจว่าหน้า Dashboard เปิดได้และชื่อบัญชีถูกต้อง
6. เมื่อทดสอบเสร็จให้ออกจากระบบ โดยเฉพาะเมื่อใช้คอมพิวเตอร์ร่วมกัน

| ผู้ทดสอบ | ชื่อผู้ใช้ | Role ในระบบ | ขอบเขตหลัก |
|---|---|---|---|
| FC | `Pichaya@oceanrover.com` | FINANCE | ราคา ใบเสนอราคา ใบแจ้งหนี้ การรับชำระ และรายงานกำไร |
| Chief Engineer | `Itthipol@oceanrover.com` | BOAT_YARD_MANAGER | Service Request Work Order ค่าแรง วัสดุ ผู้รับเหมาช่วง และคลัง |

**ข้อควรระวัง:** ไม่บันทึกรหัสผ่านไว้ในคู่มือ เอกสารงาน หรือช่อง Notes ของระบบ หากลิงก์หรือรหัสผ่านถูกส่งต่อผิดคน ให้แจ้ง Admin เพื่อยกเลิกลิงก์หรือเปลี่ยนรหัสทันที

## 3 กติกาการทดลองใช้

- ใช้ข้อมูลทดสอบที่ระบุคำว่า `PILOT` หรือ `TRAINING` ใน Reference หรือ Notes
- ห้ามส่งข้อความจริงให้ลูกค้า ห้ามส่งอีเมลหรือ WhatsApp และห้ามโอนหรือรับเงินจริง
- ห้ามนำเลขบัญชี เอกสารลูกค้า หรือข้อมูลส่วนบุคคลจริงเข้าสู่ระบบโดยไม่จำเป็น
- ค่า Default Discount ต้องเริ่มที่ `0%` ส่วนลดจากไฟล์ต้นทางเป็นข้อมูลอ้างอิงและห้ามนำไปใช้กับลูกค้าอัตโนมัติ
- ห้ามเปลี่ยน Standard Rate หรือรหัสบัญชีโดยไม่มีหลักฐานและผู้ตรวจรับ
- ก่อนกด Save ให้ตรวจ Customer Boat Reference วันที่ จำนวนเงิน VAT และสถานะทุกครั้ง
- หากเห็นข้อมูลผิดสิทธิ์ หรือสามารถแก้ข้อมูลที่ไม่เกี่ยวกับหน้าที่ ให้หยุดและรายงานเป็นปัญหาสิทธิ์ทันที
- เมื่อพบข้อความ `403 Forbidden` ในส่วนที่คู่มือนี้ระบุว่าไม่มีสิทธิ์ ถือว่าเป็นพฤติกรรมที่คาดไว้ ไม่ต้องพยายามข้ามสิทธิ์

### เหตุผลที่ไม่ควรให้ Admin ทำคนเดียว

Admin ไม่ได้อยู่หน้างานและไม่ใช่เจ้าของสมุดบัญชี จึงอาจไม่ทราบว่าต้นทุนหรือรหัสบัญชีใดถูกต้อง การแยกหน้าที่ทำให้ต้นทุนมาจากผู้รู้หน้างาน ราคาและการจัดหมวดมาจาก FC และ Admin สามารถตรวจประวัติหรือจำกัดสิทธิ์ได้โดยไม่กลายเป็นคอขวด

### ข้อจำกัดของ V1 ที่ต้องควบคุมด้วยวิธีปฏิบัติ

ปัจจุบัน Pricing Master อนุญาตให้ `SUPER_ADMIN` และ `FINANCE` แก้ไข และระบบบันทึกผู้แก้ไขกับผู้อนุมัติจากบัญชีที่กดบันทึก ยังไม่ได้บังคับให้ผู้อนุมัติเป็นคนละคน ระหว่าง Pilot จึงต้องมีหลักฐานอนุมัติก่อนแก้ราคา เช่น เลขที่เอกสาร อีเมลอนุมัติ หรือบันทึกประชุม และบันทึก Source Version หรือ Notes ให้ค้นย้อนหลังได้

## 5 คู่มือสำหรับ FC

### 5.1 สิ่งที่ FC ต้องตรวจ

- Pricing Master แสดงราคาปกติ ราคาปัจจุบัน ส่วนลด และต้นทุนตรงอย่างถูกต้อง
- ใบเสนอราคาใช้ราคาและต้นทุน snapshot ณ วันที่ออกเอกสาร
- ใบแจ้งหนี้ตรงกับใบเสนอราคาหรือรายการที่อนุมัติ
- Payment ตัดยอดคงเหลือของ Invoice ถูกต้องและมี Reference ตรวจสอบได้
- Job Margin แยก Labor Material และ Contractor Cost และคำนวณ Gross Profit ถูกต้อง
- Export CSV เปิดใช้งานได้และยอดรวมตรงกับหน้าจอ
- ประวัติการเปลี่ยนราคามีวัน ผู้แก้ ผู้อนุมัติ และแหล่งข้อมูล

### 5.2 ตรวจ Pricing Master

เส้นทาง: **Pricing and Quotations > Pricing Master** หรือ `/pricing-master`

1. ค้นหาบริการด้วย Code หรือชื่อบริการ
2. เปิดรายละเอียดรายการที่ต้องตรวจ
3. เทียบค่าต่อไปนี้กับเอกสารต้นทาง
   - Rate THB หรือราคาปัจจุบันที่อนุมัติ
   - Full or Normal Rate THB
   - Default Discount ซึ่งควรเป็น `0%` เว้นแต่มีอนุมัติเฉพาะ
   - Source Discount Reference ซึ่งใช้เพื่ออ้างอิงเท่านั้น
   - Direct Cost THB
   - Revenue GL Code และ Cost GL Code
   - Revenue P and L Category และ Cost P and L Category
   - Calculation Type Quote Rule Price Status และ Effective Date
   - Source Version และ Cost Basis
4. หากข้อมูลถูกต้อง ให้บันทึกผลตรวจในแบบฟอร์มท้ายคู่มือโดยไม่กด Save
5. หากต้องแก้ไข ให้ดำเนินการตามหัวข้อ 7 ก่อนกด Save
6. หลัง Save ให้เปิด **Price change history** และตรวจผู้เปลี่ยน ผู้อนุมัติ เวลา และ Source

### 5.3 ตรวจ Quotations

เส้นทาง: **Pricing and Quotations > Quotations** หรือ `/quotations`

1. เปิดใบเสนอราคา `PILOT` ที่ Admin เตรียมไว้ หรือสร้างข้อมูลทดสอบตามที่ได้รับมอบหมาย
2. ตรวจ Customer Boat วันที่หมดอายุ VAT และรายละเอียดรายการ
3. ตรวจว่าราคาไม่ดึง Source Discount Reference มาเป็นส่วนลดลูกค้า
4. ตรวจ Discount ของแต่ละบรรทัด โดยค่าเริ่มต้นต้องเป็น `0%`
5. ตรวจยอดก่อน VAT VAT และยอดรวม
6. หากแปลงเป็น Invoice ให้ตรวจว่ารายการและยอดไม่เปลี่ยนโดยไม่มีเหตุผล

### 5.4 ตรวจ Invoices และ Payments

เส้นทาง: `/invoices` และ `/payments`

1. ใช้ Invoice ทดสอบ ห้ามใช้เลขอ้างอิงธนาคารจริง
2. ตรวจ Invoice Date Due Date Customer Boat และยอดคงเหลือ
3. บันทึก Payment ทดสอบด้วย Reference ที่ขึ้นต้น `TRAINING`
4. ตรวจกรณีชำระบางส่วนและชำระครบว่าสถานะและยอดคงเหลือถูกต้อง
5. ห้ามบันทึกการรับเงินจริงระหว่าง Pilot

### 5.5 ตรวจ Job Margin และ Export

เส้นทาง: `/reports/job-margin`

1. เลือก Work Order ที่ปิดงานแล้ว
2. เทียบ Revenue กับ Quotation หรือ Invoice ที่เกี่ยวข้อง
3. เทียบ Labor Cost กับ Timesheet หรือ Labor Cost ของ Work Order
4. เทียบ Material Cost กับ Material Usage และ Stock Movement
5. เทียบ Contractor Cost กับใบเสนอราคาหรือ PO ผู้รับเหมาช่วง
6. ตรวจสูตร `Gross Profit = Revenue - Labor - Material - Contractor`
7. กด Export CSV และเปิดตรวจหัวคอลัมน์กับยอดรวม

## 6 คู่มือสำหรับ Chief Engineer

### 6.1 สิ่งที่ Chief Engineer ต้องตรวจ

- Service Request แปลงเป็น Work Order และรักษาความเชื่อมโยงกับ Customer และ Boat
- Work Order แสดง Scope Priority Location ผู้รับผิดชอบ และสถานะถูกต้อง
- ค่าแรงมาจากชั่วโมงและอัตราค่าแรง หรือยอดค่าแรงที่มีหลักฐาน
- วัสดุมีชื่อ จำนวน หน่วย ต้นทุนต่อหน่วย และยอดรวมถูกต้อง
- ผู้รับเหมาช่วงมี Scope ใบเสนอราคา ต้นทุนที่อนุมัติ และ Reference
- Stock In Stock Out Adjustment และ Issue to Work Order ถูกต้อง
- ต้นทุนรวมของงานเท่ากับ Labor Material และ Contractor Cost

### 6.2 ตรวจ Service Request และ Work Order

เส้นทาง: `/service-requests` และ `/work-orders`

1. เปิด Service Request ที่มี Reference `PILOT`
2. ตรวจ Customer Boat Category Title Description Priority Location และ Required Inspection
3. สร้างหรือเปิด Work Order ที่เชื่อมกับ Service Request
4. ตรวจ Scope งาน Task ผู้รับผิดชอบ และสถานะ
5. ห้ามเริ่มงานจริงจากรายการทดสอบ

### 6.3 บันทึกค่าแรง

ในหน้า Work Order ให้เปิดแท็บ **Labor** หรือ **Costing**

1. เลือกช่าง วันที่ เวลาเริ่ม เวลาสิ้นสุด และจำนวนชั่วโมง
2. ตรวจ Hourly Rate จากอัตราที่อนุมัติ
3. ตรวจ Total Cost ก่อน Save
4. หากบันทึกยอด Labor Cost โดยตรง ต้องมีเอกสารหรือรายละเอียดประกอบ
5. ห้ามรวมเวลาซ้ำ หรือรวมเวลาของงานอื่นไว้ใน Work Order เดียวกัน

### 6.4 บันทึกวัสดุและคลัง

ในหน้า Work Order ใช้ Material Usage และตรวจ `/inventory` กับ `/inventory/movements`

1. เลือกหรือระบุวัสดุให้ตรงกับรายการคลัง
2. บันทึก Quantity Unit และ Unit Cost ตามเอกสารล่าสุด
3. ผูก Reference กับ Work Order
4. ตรวจว่า Total Cost เท่ากับ Quantity คูณ Unit Cost
5. ตรวจ Stock Movement ว่าทิศทางและจำนวนคงเหลือถูกต้อง
6. หากต้นทุนผิด ให้แก้ข้อมูลต้นทางหรือแจ้ง FC ห้ามปรับตัวเลขเพื่อให้ Margin ดูดีขึ้น

### 6.5 บันทึกต้นทุนผู้รับเหมาช่วง

1. ระบุ Scope งานและสิ่งที่รวมและไม่รวมในราคา
2. แนบหรืออ้างอิงใบเสนอราคาของผู้รับเหมา
3. เปรียบเทียบราคา เงื่อนไข และกำหนดส่ง
4. บันทึกต้นทุนที่ได้รับอนุมัติ ไม่ใช้ราคาขายให้ลูกค้าแทนต้นทุน
5. แจ้ง FC เมื่อมี Variation หรือค่าใช้จ่ายเกินวงเงิน

### 6.6 ขอบเขตที่ Chief Engineer ไม่ควรแก้

- Standard Rate Current Rate Default Discount และ Pilot Rate
- Revenue GL Cost GL และ P and L Category
- Invoice Payment และการกระทบยอดบัญชี
- User Role Deployment หรือ Environment Configuration

บัญชี `BOAT_YARD_MANAGER` ถูกออกแบบให้ทำงานด้านปฏิบัติการและต้นทุนงาน แต่ไม่มีสิทธิ์แก้ Pricing Master และรายงานการเงินบางรายการ หากระบบยอมให้แก้รายการข้างต้น ให้รายงานเป็นปัญหาสิทธิ์

## 7 วิธีแก้ข้อมูลจริงหรือข้อมูลตั้งต้น

### 7.1 ขั้นตอนก่อนแก้ทุกครั้ง

1. ระบุรายการเดิม รายการใหม่ เหตุผล และวันที่มีผล
2. ระบุแหล่งข้อมูล เช่น เลขที่ใบเสนอราคา Supplier ใบอนุมัติ หรือ Rate Card Version
3. ให้เจ้าของข้อมูลตรวจตามตารางความรับผิดชอบ
4. ใช้ Staging ทดสอบผลกระทบกับ Quotation และ Job Margin ก่อน
5. บันทึกผลทดสอบและขออนุมัติก่อนนำไป Production

### 7.2 การแก้ต้นทุนต่อบริการ

Chief Engineer จัดทำต้นทุนและหลักฐาน แล้วส่งให้ FC ตรวจว่าเป็นต้นทุนตรงและจัดหมวดถูกต้อง FC จึงแก้ `Direct Cost THB`, `Cost GL Code`, `Cost P and L Category` และ `Cost Basis` ใน Pricing Master พร้อมระบุ Source Version หลังบันทึกต้องตรวจ Price change history

### 7.3 การแก้ต้นทุนจริงของ Work Order

Chief Engineer แก้ที่ข้อมูลหน้างาน ได้แก่ Timesheet Material Usage Stock Movement หรือ Contractor Cost ไม่ควรย้อนกลับไปเปลี่ยน Direct Cost ใน Pricing Master เพื่อให้ตรงกับงานใดงานหนึ่ง เพราะ Direct Cost เป็นค่ามาตรฐานสำหรับงานใหม่ ส่วน Work Order Cost เป็นต้นทุนจริงของงานนั้น

### 7.4 การแก้ราคาและส่วนลด

- การเปลี่ยนถาวร: FC แก้ Standard หรือ Current Rate หลังมีอนุมัติ
- การทดลองชั่วคราว: ใช้ Pilot Rate และบันทึก Pilot Note พร้อมวันสิ้นสุด
- ส่วนลดลูกค้า: เริ่มที่ `0%` และใช้เฉพาะเมื่อมีอำนาจอนุมัติ
- Source Discount Reference: เก็บเป็นข้อมูลอ้างอิง ห้ามใช้เป็นส่วนลดลูกค้าอัตโนมัติ

### 7.5 เมื่อใดที่ Admin ต้องเป็นผู้ดำเนินการ

Admin ต้องดำเนินการเมื่อเป็นเรื่องบัญชีผู้ใช้ Role การเปิดหรือปิดสิทธิ์ Environment Variable Deployment Migration การกู้คืนข้อมูล หรือการเปลี่ยนโครงสร้างระบบ Admin สามารถเป็นผู้สำรองให้ FC ได้ในกรณีฉุกเฉิน แต่ต้องบันทึกเหตุผลและให้ FC ตรวจย้อนหลัง

## 8 ชุดทดสอบสำหรับ Pilot

### 8.1 FC

- [ ] เปิด Pricing Master และตรวจอย่างน้อย 10 บริการจากหลาย Category
- [ ] ยืนยัน Default Discount เป็น 0% สำหรับข้อมูลที่ไม่มีอนุมัติส่วนลด
- [ ] ตรวจ Direct Cost GL และ P and L อย่างน้อย 5 บริการ
- [ ] ตรวจ Price change history อย่างน้อย 2 รายการ
- [ ] ตรวจ Quotation 1 รายการและแปลงเป็น Invoice ทดสอบ
- [ ] บันทึก Payment บางส่วนและ Payment ครบด้วยข้อมูล TRAINING

## 9 วิธีรายงานปัญหา

รายงานหนึ่งปัญหาต่อหนึ่งรายการ โดยระบุ:

| หัวข้อ | สิ่งที่ต้องบันทึก |
|---|---|
| วันที่และเวลา | เวลาประมาณที่พบปัญหา |
| Role | FINANCE หรือ BOAT_YARD_MANAGER |
| Route | เช่น `/pricing-master` หรือ `/work-orders/...` |
| Reference | รหัส PILOT TRAINING หรือเลขเอกสารทดสอบ |
| ขั้นตอน | ทำอะไรก่อนเกิดปัญหา |
| ผลที่คาดหวัง | ระบบควรแสดงหรือคำนวณอย่างไร |
| ผลที่เกิดขึ้น | ข้อความผิดพลาดและค่าที่เห็นจริง |
| หลักฐาน | Screenshot โดยปิดข้อมูลส่วนบุคคล |
| ความรุนแรง | Blocker High Medium หรือ Low |

หยุดทดสอบและแจ้ง Admin ทันทีเมื่อพบข้อมูลลูกค้าคนอื่น การแก้ไขข้ามสิทธิ์ ยอดเงินผิด ความสัมพันธ์ Invoice Payment ผิด หรือการส่งข้อความออกสู่ภายนอก

## 10 เกณฑ์ยืนยันจากผู้ทดสอบ

### FC ยืนยันเมื่อ

- รายการราคาและต้นทุนที่สุ่มตรวจตรงกับหลักฐาน
- Quotation Invoice Payment และ Job Margin เชื่อมโยงและคำนวณถูกต้อง
- รายงานและ Export ใช้ตรวจสอบบัญชีได้
- รายการ GL และ P and L ที่ขาดได้รับการระบุครบ
- ขอบเขตการอนุมัติราคาและส่วนลดได้รับความเห็นชอบ

### Chief Engineer ยืนยันเมื่อ

- Service Request Work Order Timesheet Material และ Contractor workflow ตรงกับงานจริง
- ต้นทุนงานบันทึกได้โดยไม่ต้องให้ Admin ทำแทน
- สต็อกและต้นทุนวัสดุเชื่อมกับ Work Order ได้
- ขอบเขตสิทธิ์ไม่เปิดให้แก้ข้อมูลการเงินที่ไม่เกี่ยวข้อง
- ระบุ field หรือขั้นตอนที่ต้องปรับก่อน Pilot จริงครบแล้ว
