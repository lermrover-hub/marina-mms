## 5. ขั้นตอนการจองใหม่ (New Booking Workflow)

**สถานะ: ✅ ใช้งานได้จริง (แยกเป็น 2 รูปแบบ)**

ระบบไม่มีตัวช่วยสร้าง "การจองใหม่" แบบรวมศูนย์เดียว แต่มี 2 ขั้นตอนแยกตามวัตถุประสงค์:

1. **การจองแท่นลากเรือ (ปล่อยเรือ/นำเรือขึ้น/ยกเรือขึ้นอู่)** — `app/(dashboard)/ramp-bookings/new/page.tsx`
   - เลือกประเภทปฏิบัติการ (`OPERATION_TYPES` — รวมปล่อยเรือ นำเรือขึ้น ยกเรือขึ้นอู่)
   - บันทึกกินน้ำลึกเรือ ความสูงรถพ่วง และข้อมูลนำเข้าสำหรับคำนวณความปลอดภัยระดับน้ำ; บังคับให้กรอกกินน้ำลึกและความสูงรถพ่วงสำหรับปฏิบัติการ `LAUNCH`/`RETRIEVAL` ก่อนบันทึก (`if ((opType === "LAUNCH" || opType === "RETRIEVAL") && (draft <= 0 || trailer <= 0)) ...`)
   - ตรวจสอบระดับน้ำแบบเรียลไทม์ผ่าน `/api/tide/calculate` ขณะกรอกฟอร์ม
   - API: `app/api/db/ramp-bookings` (+ `[id]`)

2. **การจองบริการผ่านใบเสนอราคา** — `app/(dashboard)/quotations/new/page.tsx`
   - คำอธิบายบริการแบบข้อความอิสระ พร้อมตัวสร้างรายการหลายบริการ (ดูข้อ 6)
   - แปลงต่อไปเป็นใบสั่งงาน / สัญญา / ใบแจ้งหนี้ (ดูข้อ 9, 12)

**สถานะ: ✅ ใช้งานได้จริง**

## 7. บริการรถบรรทุก / รถพ่วง / งานยก (Truck / Trailer / Lifting Services)

**สถานะ: ✅ ใช้งานได้จริงในฐานะรายการราคา; 🟡 ใช้งานได้บางส่วนในฐานะฟิลด์เฉพาะของการจอง**
- บริการเหล่านี้ **ไม่ใช่** ฟอร์มย่อยแยกต่างหาก แต่คิดราคาและบันทึกเป็นรายการในใบเสนอราคาภายใต้หมวดหมู่ `Towing Truck Cost` และ `Yard Services` (ซึ่งรวมถึงรายการยกไฮดรอลิกและเครน)
- รายการราคาที่ยืนยันแล้ว (`scripts/import-rate-card.sql`): `TRUCK_MINI_DAY`, `TRUCK_MINI_NIGHT`, `TRUCK_MINI_LATE`, `TRUCK_BIG_DAY`, `TRUCK_BIG_BEFORE_MID`, `TRUCK_BIG_AFTER_MID` (หน่วย `trip` ทั้งหมด); `LIFT_HYD_12T` (ยกไฮดรอลิก ≤12 ตัน), `LIFT_CRANE_12_18`, `LIFT_CRANE_OVER18`, `TRAILER_GENERAL`, `TRAILER_REPAIR`, `STAND_DAY/WEEK/MONTH`, `YARD_MOVE`, `YARD_BIG_TRUCK`, `YARD_EMERGENCY`
- **ความสูงรถพ่วง** (ไม่ใช่ค่าเช่ารถพ่วง) ถูกบันทึกแยกต่างหากในฟอร์มจองแท่นลากเรือ เพื่อใช้เป็นข้อมูลคำนวณความปลอดภัยระดับน้ำ (ดูข้อ 5, 8) — เป็นคนละกรณีกับค่าเช่ารถพ่วงในรายการราคา
- **กฎธุรกิจ — รถบรรทุกคิดราคาแบบไป-กลับ (ยืนยันแล้ว):** บริการรถบรรทุกและเครนคิดราคาแบบ **ไป-กลับ (round trip)** เป็นค่าเริ่มต้น การคิดราคาเที่ยวเดียวต้องได้รับอนุมัติเป็นลายลักษณ์อักษรจากผู้จัดการ แหล่งอ้างอิง: `ai-agents/PRICING_RULES.md` ข้อ 4 ในทางปฏิบัติหมายความว่างานรถบรรทุกจะมีค่าใช้จ่ายเทียบเท่า 2 เที่ยว (ไป + กลับ) เว้นแต่ผู้จัดการจะอนุมัติและบันทึกข้อยกเว้นเที่ยวเดียวเป็นลายลักษณ์อักษร
- **กฎธุรกิจ — การผูกรหัสบัญชีทั่วไป (GL) ของงานยกไฮดรอลิก (ยืนยันในข้อมูล แต่ไม่ได้บังคับใน schema):** รายการ `LIFT_HYD_12T` และรายการยก/เครน/รถบรรทุกอื่น ๆ ถูกระบุ `GL: 4140` ในข้อความคำอธิบายที่นำเข้า (`scripts/import-rate-card.sql`) **ไม่มีคอลัมน์ `gl_code`** แยกต่างหากใน Prisma model `PricingMaster` ที่ใช้งานจริง — การผูกรหัสนี้เป็นข้อตกลงด้านข้อมูล/เอกสารเท่านั้น ไม่ได้บังคับใช้เป็นฟิลด์ฐานข้อมูล ห้ามนำเสนอว่าเป็นฟีเจอร์ที่ค้นหา/ตรวจสอบได้ในระบบ

## 8. เครื่องคำนวณช่วงเวลาระดับน้ำ (Tide Window Calculator)

**สถานะ: ✅ ใช้งานได้จริง**
- หน้าคำนวณแยกต่างหาก: `app/(dashboard)/ramp-bookings/tide-calculator/page.tsx`
- ฝังอยู่ในฟอร์มสร้างการจองแท่นลากเรือด้วย (`ramp-bookings/new/page.tsx`)
- API: `app/api/tide/calculate/route.ts` (ตั้งเป็น `force-dynamic` ตั้งแต่ commit `9126224` เพื่อป้องกันผลลัพธ์ที่ถูกแคชค้าง)
- **สูตรคำนวณ (ยืนยันแล้ว จาก `ai-agents/TIDE_RULES.md`):**
  ```
  minimum_required_actual_depth_m = boat_draft_m + trailer_height_m + safety_clearance_m
  minimum_required_tide_table_height_m = minimum_required_actual_depth_m − ramp_offset_m
  ปลอดภัย (SAFE) เมื่อ predicted_tide_height_m ≥ minimum_required_tide_table_height_m
  ```
- **ค่าเริ่มต้นที่ได้รับอนุมัติ:** `trailer_height_m = 0.70`, `safety_clearance_m = 0.10`, `ramp_offset_m = −1.00` เก็บไว้ใน `mms_agent_config` (agent_id `"tide"`) และมีค่าสำรองใน `ai-agents/lib/agent-config.js` เปลี่ยนแปลงได้เฉพาะผ่าน **ตั้งค่า → กฎ AI Agent → Tide Agent** ในเว็บแอปเท่านั้น — ไม่ได้ฝังตายตัวในโค้ด
- เครื่องคำนวณให้ผลลัพธ์เป็นช่วงเวลารายชั่วโมงของวันนั้น สถานะปลอดภัย/ไม่ปลอดภัยต่อช่วง ชั่วโมงที่ปลอดภัยที่เร็วที่สุด และช่วงเวลาปลอดภัย
- **กฎธุรกิจ — เป็นเพียงเครื่องมือช่วยวางแผนเท่านั้น (ยืนยันแล้ว ระบุชัดเจนในซอร์ส):** `ai-agents/TIDE_RULES.md` ข้อ 4 "กฎการอนุมัติขั้นสุดท้ายโดยต้นเรือ (Dockmaster)": *"การจัดประเภท SAFE ของระบบเป็นเพียงคำแนะนำเท่านั้น... ต้นเรือหรือหัวหน้างานปฏิบัติการต้องยืนยันด้วยสายตาจริงในวันปฏิบัติงานทุกครั้งสำหรับการปล่อยเรือและนำเรือขึ้นทุกครั้ง... AI agent ห้ามออกคำยืนยัน 'เรือพร้อมปล่อย' โดยเด็ดขาด"* ผลลัพธ์จาก API/agent จะมีฟิลด์ `warning` เสมอ ระบุว่าการคาดการณ์ระดับน้ำอาจแตกต่างจากระดับน้ำจริง และต้องมีการยืนยันขั้นสุดท้ายในวันปฏิบัติงาน — ฟิลด์นี้ "ต้องไม่ถูกซ่อนหรือลบออกเด็ดขาด"
- หากไม่มีข้อมูลระดับน้ำสำหรับวันที่ร้องขอ ระบบต้องส่งคืนสถานะ `no_tide_data` และห้ามดำเนินการจองต่อจนกว่าเจ้าหน้าที่จะจัดหาและกรอกข้อมูลระดับน้ำด้วยตนเอง (ข้อ 5 ของ `TIDE_RULES.md`)

**⚠️ คำแนะนำสำหรับเจ้าหน้าที่ (บังคับ):** ให้ถือว่าผลลัพธ์จากเครื่องคำนวณระดับน้ำเป็นเพียงเครื่องมือช่วยวางแผนเท่านั้น ต้นเรือหรือหัวหน้างานปฏิบัติการต้องยืนยันระดับน้ำจริงด้วยตนเองในวันปฏิบัติงานทุกครั้ง ก่อนปล่อยเรือหรือนำเรือขึ้นทุกครั้ง

## 9. พฤติกรรมใบเสนอราคา / การคิดราคา (Quotation / Pricing Behavior)

**สถานะ: ✅ ใช้งานได้จริง**
- รายการ/รายละเอียด/สร้างใบเสนอราคา: `app/(dashboard)/quotations/*` API: `app/api/db/quotations`, `app/api/db/quotation-items`
- แหล่งข้อมูลราคาหลัก: `PricingMaster` (Prisma model ใน `prisma/schema.prisma`) เข้าถึงผ่าน `GET /api/pricing-master?isActive=true` ฟิลด์ที่ยืนยันใน schema: `code`, `serviceNameEn`, `serviceNameTh`, `category`, `unit`, `rateThb`, `description`, `notes`, `isActive`
- **การร่างใบเสนอราคาด้วย AI** มีอยู่จริง (`app/api/quotations/ai-generate/route.ts`) สร้างใบเสนอราคาแบบร่าง 3–10 รายการ จำกัดหมวดหมู่ จากคำอธิบายงานแบบข้อความอิสระ เป็นสกุลเงินบาท ไม่รวม VAT นี่คือ **เครื่องมือร่างเอกสาร** ไม่ใช่ระบบส่งอัตโนมัติ — ผลลัพธ์ยังต้องผ่านการตรวจสอบก่อนกลายเป็นใบเสนอราคาที่ส่งให้ลูกค้าจริง
- **กฎ VAT (ยืนยันแล้ว):** `taxAmount = round(subtotal × vat_pct/100)`; `grandTotal = subtotal + taxAmount` ค่าเริ่มต้น `vat_pct = 7` อ่านจาก `mms_agent_config` ไม่ฝังตายตัวในโค้ด ตาม `ai-agents/PRICING_RULES.md` ข้อ 6
- **กฎเงินมัดจำ (ยืนยันแล้ว):** `depositRequired = round(grandTotal × deposit_pct/100)` ค่าเริ่มต้น `deposit_pct = 50`
- **กฎอายุใบเสนอราคา (ยืนยันแล้ว):** `validUntil = today + valid_days` (ค่าเริ่มต้น 7 วัน) ใบเสนอราคาควรเปลี่ยนสถานะเป็น `expired` หลังจากวันดังกล่าว
- **กฎการจำแนกประเภทเรือเร็ว (ยืนยันแล้ว ใช้งานทั้งในโค้ดเว็บและ agent — `lib/speedboat-classification.ts` และ `ai-agents/lib/speedboat-classification.js`):** การจำแนกประเภท **อิงตามความยาวเรือ (LOA) เป็นหลัก ไม่ใช่จำนวนเครื่องยนต์** จำนวนเครื่องยนต์เป็นเพียงสัญญาณยืนยันเท่านั้น เมื่อจำนวนเครื่องยนต์กับกลุ่มที่ได้จาก LOA ไม่ตรงกัน ให้ยึด LOA เป็นหลักและต้องแสดงคำเตือนความไม่ตรงกัน
  - 1 เครื่องยนต์ ≤27 ฟุต → ปกติ, `RAMP_1OB`
  - 2 เครื่องยนต์ 27–40 ฟุต → ปกติ/ปานกลาง, `RAMP_2OB`
  - 3 เครื่องยนต์ 40–47 ฟุต → ปานกลาง/สูง, `RAMP_3OB`
  - 4 เครื่องยนต์ 47–55 ฟุต → สูง/ต้องดูแลพิเศษ, `RAMP_3OB`
  - เงื่อนไขยกระดับความเสี่ยงเพิ่มเติม (+1 ระดับต่อรายการ): ความกว้าง ≥9 ฟุต, กินน้ำลึก ≥2.5 ฟุต, น้ำหนัก ≥4,000 กก.
- **ข้อกล่าวอ้างเรื่องการยกเรือเร็วขึ้นคิดราคาแบบเหมาจ่าย (flat-rate): ⚪ ไม่สามารถยืนยันได้** ไม่พบคำว่า "flat rate" หรือ "flat-rate" ที่ใดในซอร์สโค้ดนี้เลย รายการราคาที่เกี่ยวข้องกับการยกเรือขึ้นอู่คิดราคาแยกตามเที่ยว/วัน/ครั้ง/ขาตั้งต่อวัน ไม่ใช่ค่าธรรมเนียมเหมาจ่ายรายการเดียว **ห้ามระบุว่าการยกเรือเร็วขึ้นอู่เป็นราคาเหมาจ่ายในเอกสารที่ใช้กับลูกค้า** เว้นแต่ฝ่ายการเงินจะยืนยันกับรายการราคาปัจจุบันที่ใช้งานจริง
- **กฎการคิดราคางานภายนอก (Outsourced) (ยืนยันแล้ว `PRICING_RULES.md` ข้อ 5):** งานเครื่องยนต์/ช่างกล และงานทาสี/ขัดเงา/กันเพรียง/เจลโค้ท **ห้าม** ให้ AI คิดราคาอัตโนมัติ ต้องส่งต่อให้ผู้จัดการติดต่อลูกค้าโดยตรงและประสานงานกับช่าง/ผู้รับเหมาก่อนกำหนดราคา — AI agent ห้ามติดต่อลูกค้าโดยตรงหรือสร้างใบเสนอราคาที่ส่งให้ลูกค้าในหมวดหมู่เหล่านี้
- **ราคาทดลอง (`pilotRateThb`): ⚪ ไม่สามารถยืนยันได้** `PRICING_RULES.md` อธิบายฟิลด์นี้ไว้ แต่ **ไม่มีอยู่จริง** ใน Prisma schema ของ `PricingMaster` ในปัจจุบัน ให้ถือว่า "ราคาทดลอง" เป็นฟีเจอร์ที่ยังไม่ได้บันทึกใน schema จนกว่าจะตรวจสอบกับฐานข้อมูลจริง
- **ฟิลด์รหัสบัญชีทั่วไป (GL): ⚪ ไม่สามารถยืนยันได้ / ไม่ได้บังคับใน schema** ดูข้อ 7 — รหัส GL ปรากฏเฉพาะในข้อความบันทึกที่นำเข้าเท่านั้น ไม่ใช่คอลัมน์ฐานข้อมูลที่มีโครงสร้าง

## 13. รายการตรวจสอบประจำวันสำหรับเจ้าหน้าที่มารีน่า (Daily Operation Checklist)

รายการต่อไปนี้รวบรวมจากฟีเจอร์ที่ใช้งานได้จริงข้างต้น เป็นแนวทางปฏิบัติงาน ไม่ใช่ฟีเจอร์เช็คลิสต์ในระบบที่ยืนยันจากโค้ด (ไม่พบวิดเจ็ตเช็คลิสต์ในแอปสำหรับรายการนี้โดยเฉพาะ)

1. **เปิดผังพื้นที่/ผังช่องจอด** (`/berths`) — ตรวจสอบช่องจอดที่ใช้งานอยู่ จองไว้ และว่างของวันนี้
2. **ตรวจสอบปฏิทินการจอง** (`/berths/calendar`) — ทบทวนเรือที่จะเข้า/ออกในสัปดาห์นี้
3. **ทบทวนการจองแท่นลากเรือของวันนี้** (`/ramp-bookings`) — ตรวจสอบประเภทปฏิบัติการ (ปล่อยเรือ/นำเรือขึ้น/ยกขึ้นอู่) เจ้าหน้าที่ที่มอบหมาย และเวลานัดหมาย
4. **รันเครื่องคำนวณช่วงเวลาระดับน้ำ** สำหรับทุกการปล่อยเรือ/นำเรือขึ้นที่กำหนดไว้ (`/ramp-bookings/tide-calculator` หรือในฟอร์มจองโดยตรง) — บันทึกช่วงเวลาปลอดภัยที่คาดการณ์ไว้
5. **ยืนยันระดับน้ำจริงด้วยตนเองในสถานที่จริง** ก่อนปล่อยเรือ/นำเรือขึ้นทุกครั้ง — เครื่องคำนวณระดับน้ำเป็นเพียงเครื่องมือช่วยวางแผน การตรวจสอบด้วยตนเองนี้เป็นข้อบังคับ (ดูข้อ 8)
6. **ตรวจสอบการแจ้งเตือน** (`/notifications`) — ใบแจ้งหนี้ค้างชำระ การแจ้งเตือนสัญญา/ประกันภัย การแจ้งเตือนใบสั่งงานที่ล่าช้า
7. **ทบทวนคำขอบริการ/ใบสั่งงานที่เปิดอยู่** (`/service-requests`, `/work-orders`) — ตรวจสอบสถานะงานและวัสดุ
8. **บันทึกเหตุการณ์ทันที** ผ่าน `/incidents/new` หากเกิดเหตุด้านความปลอดภัยหรือความเสียหายระหว่างกะทำงาน
9. **บันทึกการเคลื่อนย้ายเรือ** (`/movements/new`) สำหรับการย้ายเรือในลาน/ท่าเทียบเรือ
10. **สิ้นสุดกะทำงาน:** ตรวจสอบว่าใบเสนอราคา ใบแจ้งหนี้ และการชำระเงินของวันนั้นถูกบันทึกครบถ้วนและบันทึกสำเร็จแล้ว

## 14. รายการตรวจสอบการอนุมัติของผู้จัดการ (Manager Approval Checklist)

รวบรวมจากกฎที่ต้องผ่านการอนุมัติซึ่งยืนยันได้ในโค้ด/เอกสาร:

1. **การคิดราคารถบรรทุก/เครนแบบเที่ยวเดียว** — ต้องได้รับอนุมัติจากผู้จัดการพร้อมบันทึกเป็นลายลักษณ์อักษรก่อนเสนอราคา (เทียบกับค่าเริ่มต้นแบบไป-กลับ) แหล่งอ้างอิง: `PRICING_RULES.md` ข้อ 4
2. **การคิดราคางานเครื่องยนต์/ช่างกล และงานทาสี/กันเพรียง/เจลโค้ท** — ห้ามคิดราคาอัตโนมัติ ผู้จัดการต้องติดต่อลูกค้าโดยตรงและประสานงานกับช่าง/ผู้เชี่ยวชาญ/ผู้รับเหมาก่อนกำหนดราคา แหล่งอ้างอิง: `PRICING_RULES.md` ข้อ 5
3. **รายการราคาใดที่ถูกระบุว่าไม่มีข้อมูล ไม่ชัดเจน นอกนโยบาย "ติดต่อ" หรือ "เสนอราคาด้วยตนเอง"** — AI agent ต้องสร้างรายการส่งต่อ/บันทึกตรวจสอบให้ผู้จัดการ แทนที่จะเสนอราคาเอง ผู้จัดการเป็นผู้รับผิดชอบราคาสุดท้ายและการติดต่อลูกค้า แหล่งอ้างอิง: `PRICING_RULES.md` ข้อ 5
4. **การเปลี่ยนแปลงราคารายการใดรายการหนึ่งเกิน 20%** — ควรได้รับการทบทวนจากกรรมการผู้จัดการก่อนเผยแพร่ แหล่งอ้างอิง: `PRICING_RULES.md` ข้อ 11
5. **การอนุมัติคำสั่ง AI (AI Order)** — เรคคอร์ด `AiOrder` (Prisma model) มีค่าเริ่มต้น `approvalRequiredRole = "MANAGING_DIRECTOR"` ผ่านคิวอนุมัติ `ApprovalQueueItem` ก่อนดำเนินการ ยืนยันจาก schema; ควรตรวจสอบขั้นตอน UI การอนุมัติแบบเต็มรูปแบบกับศูนย์ควบคุม `/ai-agents` จริงก่อนนำไปใช้งานปฏิบัติการ
6. **การยกเว้นเงินมัดจำ** — เงินมัดจำเป็นข้อบังคับก่อนเริ่มงาน "เว้นแต่จะมีการบันทึกการยกเว้นจากผู้จัดการ" (`PRICING_RULES.md` ข้อ 7) ไม่พบ UI เฉพาะสำหรับบันทึกการยกเว้นนี้อย่างชัดเจนในการทบทวนครั้งนี้ — ถือเป็น 🟡 ใช้งานได้บางส่วน (มีกฎ แต่ยังไม่ได้ตรวจสอบการบังคับใช้ผ่าน UI/API ครบถ้วน)
7. **การเปิดใช้งาน AI Agent เขียนข้อมูลจริงในระบบผลิต** (`ENABLE_AI_AGENT_WRITES`, `ENABLE_AUTOMATION_WRITES`) — ต้องปิดใช้งานในระบบผลิตเสมอ เว้นแต่ผู้จัดการ/เจ้าของกิจการจะอนุมัติอย่างชัดแจ้งให้เปิดใช้งาน (`CLAUDE_HANDOFF.md` หัวข้อ Safety Boundaries)

## 15. การแก้ไขปัญหา (Troubleshooting)

| อาการ | สาเหตุที่เป็นไปได้ / สิ่งที่ควรตรวจสอบ | สถานะ |
